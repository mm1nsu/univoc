# Uni-VOC 장학금 챗봇 — 실행 가이드 (진짜 세세하게)

이 폴더에 있는 코드를 그대로 따라 하면 터미널에서 실제로 작동하는 장학금 매칭 챗봇을 돌려볼 수 있음. 위에서부터 순서대로만 하면 됨.

## 0. 폴더 안에 뭐가 있는지

```
uni_voc_chatbot/
├── scholarship_db.json   # 실제 크롤링 데이터로 만든 장학금 DB (33건)
├── schemas.py            # 데이터 구조 정의 (건드릴 필요 없음)
├── matching.py           # 매칭 로직 (1차 규칙필터 + 2차 LLM 판단)
├── bot_core.py           # 대화 로직 본체 (LLM 호출 + 세션 상태) - CLI/웹이 공통으로 사용
├── chatbot.py            # 터미널(CLI)에서 실행하는 파일
├── app.py                # 웹 UI(브라우저 채팅창)로 실행하는 파일 ← 새로 추가됨
├── static/index.html     # 웹 UI 화면 (app.py가 이걸 띄워줌)
├── requirements.txt      # 필요한 파이썬 패키지 목록
├── Dockerfile            # 외부 배포용 (9번 섹션 참고)
├── Procfile              # 외부 배포용 (Railway 등 buildpack 플랫폼)
└── README.md             # 이 파일
```

**둘 중 아무거나 실행하면 됨.** `chatbot.py`는 터미널 텍스트 버전, `app.py`는 브라우저에서 카톡처럼 채팅창으로 쓰는 버전. 내부 로직(매칭, 대화 흐름)은 완전히 동일함 — `bot_core.py`를 같이 가져다 씀.

## 1. 파이썬 설치 확인

터미널(맥이면 `터미널.app`, 윈도우면 `PowerShell` 또는 `cmd`)을 열고 아래 명령 실행:

```bash
python3 --version
```

`Python 3.10` 이상이면 OK. `command not found`가 뜨면 [python.org](https://www.python.org/downloads/)에서 설치부터 하고 옴 (설치할 때 윈도우는 "Add python.exe to PATH" 체크박스 꼭 체크).

윈도우에서는 `python3` 대신 `python`으로만 될 수도 있음 — 아래 명령어들에서 `python3`이 안 먹으면 `python`으로 바꿔서 시도.

## 2. 이 폴더로 이동

받은 `uni_voc_chatbot` 폴더를 원하는 위치(예: 바탕화면)에 두고, 터미널에서 그 경로로 이동:

```bash
cd 바탕화면/uni_voc_chatbot
```

(경로는 실제 압축 푼 위치에 맞게. 폴더를 터미널 창에 드래그 앤 드롭하면 경로가 자동으로 입력됨.)

## 3. 가상환경 만들기 (선택이지만 강력 추천)

가상환경을 안 쓰면 이후 다른 파이썬 프로젝트랑 패키지가 꼬일 수 있음. 딱 3줄만 추가하면 되니까 하고 가는 걸 추천.

**맥/리눅스:**
```bash
python3 -m venv venv
source venv/bin/activate
```

**윈도우 (PowerShell):**
```powershell
python -m venv venv
venv\Scripts\Activate.ps1
```

활성화되면 터미널 프롬프트 맨 앞에 `(venv)`가 붙음. 이후 모든 명령은 이 상태에서 실행.

## 4. 패키지 설치

```bash
pip install -r requirements.txt
```

`google-genai`(제미나이 API SDK)랑 `pydantic`(데이터 검증 라이브러리) 두 개가 설치됨. 1분 안쪽으로 끝남.

## 5. 제미나이 API 키 환경변수로 등록

이미 API 키는 있다고 했으니, 이걸 코드에 직접 박아넣지 말고 환경변수로 등록하는 게 안전함(실수로 남한테 코드 공유해도 키가 노출 안 됨).

**맥/리눅스 — 지금 터미널 세션에서만 쓸 거면:**
```bash
export GEMINI_API_KEY="여기에_발급받은_키_붙여넣기"
```

**맥/리눅스 — 터미널 새로 열 때마다 매번 치기 귀찮으면 (영구 등록):**
```bash
echo 'export GEMINI_API_KEY="여기에_키"' >> ~/.zshrc
source ~/.zshrc
```
(쉘이 bash면 `~/.zshrc` 대신 `~/.bash_profile`)

**윈도우 (PowerShell) — 지금 세션에서만:**
```powershell
$env:GEMINI_API_KEY="여기에_발급받은_키_붙여넣기"
```

**윈도우 — 영구 등록:**
```powershell
setx GEMINI_API_KEY "여기에_키"
```
(영구 등록한 경우 터미널을 껐다 켜야 적용됨)

등록됐는지 확인:
```bash
echo $GEMINI_API_KEY        # 맥/리눅스
echo $env:GEMINI_API_KEY    # 윈도우 PowerShell
```
키 값이 그대로 출력되면 성공.

## 6. 실행

```bash
python3 chatbot.py
```

이런 식으로 시작됨:

```
[시스템] scholarship_db.json에서 33개 장학금 로드 완료

AI: 안녕! 장학금 찾는 거 도와줄게. 몇 학년이야?
학생: 3학년이요
AI: 학과는 어떻게 돼? 그리고 본인이나 부모님이 특정 지역에 오래 사신 곳 있어?
학생: 컴퓨터공학과고 대구 서구에 5년째 살아요
AI: 오케이! 직전 학기 평점이랑, 혹시 기초생활수급자/차상위/한부모/다자녀/장애/국가보훈 같은 거 해당되는 거 있어?
학생: 평점 3.8이고 해당사항 없어요
AI: 마지막으로 학자금지원구간 알아? 모르면 모른다고 해도 돼
학생: 3구간이요
AI: [매칭된 장학금 목록을 번호로 제시]
학생: 2번으로
AI: [선택한 장학금의 서류/신청방법 안내]

[시스템] 이제부터는 서류 준비하면서 궁금한 거 편하게 물어봐도 돼.

학생: 재학증명서는 어디서 떼?
AI: [계속 이어서 답변 — 프로그램이 끝나지 않고 계속 대기함]
```

**여기서부터가 이전 버전과 달라진 부분:** 장학금 안내까지 끝났다고 프로그램이 바로 종료되지 않음. 서류 준비하면서 드는 궁금증을 계속 이어서 물어볼 수 있는 "상담 모드"로 자연스럽게 전환됨. 대화 중 아무 때나 쓸 수 있는 명령어:

- `목록` / `리스트` — 매칭됐던 장학금 후보 목록 다시 보기 (재선택 가능)
- `처음부터` / `다시검색` / `리셋` — 학생 정보 싹 지우고 처음부터 재검색
- `종료` / `exit` / `quit` — 진짜로 프로그램 끝내기 (Ctrl+C 눌러도 끝남)

즉 명시적으로 종료 명령을 치기 전까진 챗봇이 계속 붙어있음.

## 6-1. 웹 UI(브라우저 채팅창)로 실행하기 ★추천

터미널 대신 브라우저에서 카톡 채팅창처럼 쓰고 싶으면 이거 실행:

```bash
python3 app.py
```

터미널에 이런 게 뜨면 성공:

```
[시스템] scholarship_db.json에서 33개 장학금 로드 완료
INFO:     Uvicorn running on http://127.0.0.1:8000
```

이 상태에서 브라우저(크롬 등) 열어서 주소창에 아래 입력:

```
http://localhost:8000
```

채팅창 화면이 뜨고, 거기서 바로 대화하면 됨. 아래쪽에 "후보 목록 다시보기" / "처음부터" 버튼도 있어서 명령어 안 외워도 됨. 종료하려면 그냥 브라우저 탭 닫고, 터미널에서 `Ctrl+C` 누르면 서버도 꺼짐.

**주의할 점:**
- 이건 로컬(내 컴퓨터 안)에서만 도는 서버임. `localhost:8000`은 내 컴퓨터에서만 열림 — 다른 사람이 인터넷으로 접속 못함. 나중에 진짜 학생들한테 배포하려면 서버 호스팅(예: Railway, Render 등)이 별도로 필요함.
- 지금은 "1인용 데모"라서 대화 세션이 서버에 하나만 존재함. 여러 명이 동시에 접속하면 같은 대화 상태를 공유하게 됨 — 여러 학생이 동시에 쓰는 서비스로 만들려면 학생별 세션 분리(로그인 또는 쿠키 기반)가 추가로 필요함.
- 서버를 껐다 켜면(`Ctrl+C` 후 재실행) 대화 내용은 초기화됨. 대화 기록을 남기려면 DB 저장 기능이 필요함 (아직 없음).

## 7. 자주 만나는 에러

| 에러 메시지 | 원인 | 해결 |
| --- | --- | --- |
| `GEMINI_API_KEY 환경변수가 설정되어 있지 않습니다` | 5번 단계를 안 했거나 새 터미널 창에서 다시 실행함 | 5번 단계 다시 (영구 등록 안 했으면 터미널 열 때마다 export 필요) |
| `PERMISSION_DENIED` / `API key not valid` | 키를 잘못 붙여넣었거나 앞뒤 공백 포함됨 | Google AI Studio에서 키 다시 복사해서 재등록 |
| `RESOURCE_EXHAUSTED` | 무료 티어 호출 한도 초과 | 몇 분 기다렸다가 재시도, 또는 결제 등록 |
| `404 model not found / no longer available` | 모델명이 바뀌었을 가능성 (제미나이는 모델이 자주 갱신됨) | `chatbot.py`, `matching.py` 안의 `MODEL = "gemini-3.6-flash"`를 에러 메시지가 알려주는 최신 모델명으로 교체 (Google AI Studio에서 사용 가능한 모델 목록도 확인 가능) |
| `pydantic.ValidationError` | scholarship_db.json을 수정하다가 형식이 깨짐 | json 문법 확인 (쉼표 빠짐, 따옴표 안 닫힘 등) |
| 매칭 결과가 항상 0개 | 오늘 날짜 기준 `is_open_application: true`인 게 적어서 그럼 (마감된 공고가 많음) | `scholarship_db.json`에서 `is_open_application`을 몇 개 `true`로 바꿔서 테스트하거나, 새 공고로 DB를 채워야 함 |
| `Direct use of automatic function calling (AFC)...` 같은 문구가 뜸 | 에러 아니고 그냥 SDK 안내성 경고문임 | 무시해도 됨. 프로그램 정상 작동함 |
| `python3 app.py` 했는데 `ModuleNotFoundError: No module named 'fastapi'` | `requirements.txt`를 web UI 추가 전 버전으로 설치했거나, venv 활성화 안 하고 설치함 | `pip install -r requirements.txt` (또는 `python -m pip install -r requirements.txt`) 다시 실행 |

## 8. 지금 이 버전의 한계 (알고 있어야 할 것)

- **방문자별 세션은 분리돼 있음** (쿠키 기반). 다만 세션이 서버 메모리에만 저장돼서 **서버 재시작하면 전부 초기화됨.** 학생 수가 많아지면 DB(Redis 등)로 세션을 옮겨야 함.
- **DB가 33건뿐임.** 재크롤링 실패한 10개 문서, 아직 안 보낸 나머지 공지들 채우면 더 정확해짐.
- **HITL(실무자 승인) 단계가 빠져있음.** 지금은 AI가 바로 서류 가이드까지 줌 — 저번에 보낸 `gemini_rag_구현가이드.md` 6장의 승인 큐 코드를 붙이면 됨.
- **로그인/본인인증이 없음.** 지금은 누구나 접속해서 씀. 실제 서비스로 나가려면 학교 계정 연동 같은 게 필요함.

이 다음에 뭘 할지는:
1. 지금 이 상태로 먼저 여러 번 대화해보면서 슬롯 추출/매칭이 실제로 잘 되는지 감 잡기
2. 아래 9번 참고해서 외부 배포까지 해보기
3. HITL 승인 단계 붙이기
4. 나머지 크롤링 데이터 채워서 DB 완성하기

순서 상관없이 되는 대로 얘기해주면 그 부분 이어서 만들어줄게.

## 9. 외부 배포 (남들도 인터넷으로 쓸 수 있게)

지금까지는 `localhost`라서 내 컴퓨터에서만 열렸음. 이제 방문자별 세션 분리도 해놨고(위 8번), `Dockerfile`/`Procfile`도 만들어놨으니 아무 호스팅 서비스에 그대로 올리면 진짜 URL이 나옴.

### 뭐부터 해야 하나

1. **GitHub에 이 폴더를 올린다.** (private repo로 올려도 됨 — `scholarship_db.json`엔 개인정보 없으니 상관없음. 단, API 키는 코드에 절대 안 박혀있으니 그대로 올려도 안전함)
2. 호스팅 서비스에 그 GitHub repo를 연결한다.
3. 호스팅 서비스 대시보드에서 환경변수 `GEMINI_API_KEY`를 등록한다 (여기가 진짜 키 값을 넣는 유일한 곳).
4. 배포 버튼 누르면 몇 분 안에 `https://프로젝트이름.호스팅도메인` 같은 진짜 주소가 생김.

### 어디에 올릴지 (가성비 순)

| 서비스 | 특징 | 비용 감 |
| --- | --- | --- |
| **Render** (추천) | GitHub repo 연결만 하면 `Dockerfile` 자동 인식해서 배포. 웹 대시보드에서 환경변수 등록 쉬움 | 무료 티어 있음(단, 트래픽 없으면 슬립 → 첫 요청 느림). 항상 켜두려면 월 $7 정도부터 |
| **Railway** | Render랑 비슷하게 쉬움, `Procfile` 자동 인식 | 매달 일정 크레딧 무료 제공 후 사용량 과금 |
| **Fly.io** | `Dockerfile` 기반, 무료 티어가 조금 더 넉넉한 편 | 소규모 앱은 거의 무료로 돌아가는 경우 많음 |
| **직접 서버(VPS)** | 학교/개인 서버 있으면 `Dockerfile`로 `docker build && docker run` 하고 nginx로 도메인 연결 | 이미 서버 있으면 추가 비용 없음, 대신 직접 관리해야 함 |

의대생이 매달 서버비 신경 쓰기 귀찮으면 **Render 무료 티어**로 일단 띄워서 반응 보고, 반응 괜찮으면 그때 유료로 전환하는 걸 추천함. 처음부터 뭘 고를지 모르겠으면 말해주면 그거 기준으로 배포 절차 더 세세하게 짜줄게 (예: Render는 "New Web Service → GitHub repo 선택 → Dockerfile 자동 감지 → Environment에 GEMINI_API_KEY 추가 → Deploy" 요렇게 클릭 몇 번이면 끝남).

### 배포 전에 꼭 확인할 것

- **API 키 과금 한도.** 배포해서 여러 명이 쓰면 Gemini API 호출량이 확 늘어남. Google AI Studio에서 사용량/한도 확인하거나 결제 알림 걸어두는 걸 추천.
- **`scholarship_db.json`이 33건뿐이라는 거.** 배포하자마자 실제 학생들이 쓰면 매칭 결과가 부실하다고 느낄 수 있음 — DB부터 좀 더 채우고 배포하는 게 나을 수도 있음.
- **HITL 없이 AI가 바로 안내한다는 거.** 잘못된 안내가 나갈 경우를 대비해서, 배포 전에 실무자 승인 단계(8번 한계에서 언급한 것)를 붙이는 걸 고려해볼 것.
